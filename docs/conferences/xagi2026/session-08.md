<details><summary>摘要（会议官网）</summary>

**问题**：大模型虽已能生成文本与代码，但课件制作仍依赖多轮智能体编排，流程冗长、成本高、交互性不足。报告将“一句话需求”到“可用的学习环境”这一过程形式化为学习环境生成（LEG）任务，并指出通用编程模型在此场景下的三个缺口：速度（单次编辑常需 200–600 秒）、可靠性（外观可伪造但交互不可用）与成本（旗舰模型参数规模过大，难以端侧部署）。教育普惠的目标要求生成模型必须同时满足实时性、可验证性与低成本，这正是 CogEvol 的出发点。

**核心方法**：CogEvol 采用“后训练为主”的路线，在公开基座模型上做三阶段训练：混合 SFT 教授两种输出契约（结构化 JSON 幻灯片与自包含 HTML 页面），随后分别用幻灯片 RL 与交互 HTML RL 强化。关键设计是奖励系统——幻灯片用 $R_{\text{slide}}=0.6\cdot\text{VLM}+0.4\cdot\text{rule}$ 的混合奖励，其中规则项编码画布利用率、碰撞、溢出等几何约束；HTML 则通过 Chromium 执行交互探针，只奖励“真正可运行”的页面，而非模型自述。训练数据来自生产环境：幻灯片由真实课件种子经规格化扩展，HTML 语料则从 119,122 次生产失败中挖掘，经执行验证后得到 53,687 条 SFT 样本。27B 模型已在生产流量中服务 220k 请求，幻灯片中位耗时 17 秒、交互页 59 秒；4B 开源版可离线运行。

**与已有工作的关系**：相对通用编码智能体（如 Claude-Code 式脚手架）的多轮迭代，CogEvol 将生成压缩为单次前向，用“执行感知”的奖励替代自然语言反馈，直接对齐渲染像素与交互行为。论文明确对比了同代旗舰编码模型（GLM-5、DeepSeek 等）：27B 以 26.9 倍更少的参数在 HTML-500 上达到 63.7，幻灯片质量 83.7，且零硬失败；而外部旗舰在严格渲染契约下甚至无法产出一张合法幻灯片。这一定位区别于对话式辅导或讲稿生成，聚焦于“可执行工件”的端到端生成。

**贡献与边界**：主要贡献是形式化 LEG 任务、构建双模态评测集（slide-std/slide-short 与 500 例交互 HTML 基准）、提出混合规则+VLM 奖励并公开 4B 权重与部署栈。边界也清晰：训练数据高度依赖生产环境与特定渲染契约，迁移到其他课件格式或学科需重新适配；评测基准内部维护，外部模型仅能通过 API 提交，存在污染风险；4B 模型质量与 27B 仍有差距，官网摘要未给出端侧具体硬件指标与能耗数据。此外，论文承认 HTML 语料存在模态偏差（69.8% 为模拟类），对代码练习、3D 可视化等类型的覆盖有限。
